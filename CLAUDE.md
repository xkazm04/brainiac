## What this is

Rust workspace (8 crates, single axum binary) + a Next.js console. Postgres 16+
(pgvector + FTS + job queue) is the only mandatory stateful dependency. See
`README.md`, `docs/ARCHITECTURE.md`, `docs/EVAL.md`, `docs/PLAN.md` (§ Crate map).

## Commands

```bash
# Postgres (pgvector) on :5433 — needed for store/retrieval/eval tests
docker compose up -d
export DATABASE_URL=postgres://brainiac:brainiac@localhost:5433/brainiac

# Build / test / lint (Rust)
cargo build --workspace
cargo test  --workspace                 # pg-backed tests self-skip without DATABASE_URL
cargo test  -p brainiac-store           # single-crate; needs DATABASE_URL
cargo fmt --all --check                 # fmt gate
cargo clippy --workspace --all-targets -- -D warnings   # lint gate

# Run the server (roles are subcommands of one binary)
cargo run -p brainiac-server -- serve      # REST on :8600
cargo run -p brainiac-server -- serve --with-worker   # one process, worker in-tree
cargo run -p brainiac-server -- worker     # in-process pipeline workers
cargo run -p brainiac-server -- mcp        # MCP surface for agents

# Eval harness ("Meridian" fixtures) — CI quality gate
cargo run -p brainiac-server -- eval --fixtures fixtures/v1 --profile retrieval \
  --baseline results/baseline.json --out results/ci-run.json
# profiles: retrieval | resolution | pipeline | contradiction | divergence |
#           extraction | docs | drift
# recalibrate deliberately: eval … --write-baseline results/<profile>-baseline.json

# Console (Next.js, port 3100)
cd console && npm ci
npm run dev            # next dev -p 3100
npm run typecheck      # tsc --noEmit
npm run test           # vitest run
npm run build          # cross-env NEXT_DIST_DIR=.next-build next build
npm run gen:api        # regenerate src/lib/api-schema.d.ts from ../openapi.json

# Full-stack deploy (one small VM): pg + server(+worker) + console
cp .env.deploy.example .env.deploy
docker compose -f docker-compose.deploy.yml --env-file .env.deploy up -d --build
```

## Conventions

- **Crate layering** (`crates/brainiac-*`): `core` = pure domain math (embed,
  fusion, rerank, scoring, temporal, health, `types`) with no DB; `store` = the
  Postgres data plane (one module per aggregate: memories, retrieval,
  governance, documents, tokens, …); `pipeline` = async workers (extract →
  contradict → resolve → compose, faithfulness, sweeps); `gateway` = BYOM
  chat/embed providers (Qwen/DashScope first) + resilience; `eval` = fixture
  profiles + regression gates; `fixtures` = the synthetic "Meridian" org;
  `publish` = KB export; `server` = axum HTTP + MCP + the `clap` CLI (main.rs).
- **Errors**: `anyhow::Result` with `.context(...)` across crates; the workspace
  lint `clippy::unwrap_used = "warn"` discourages `.unwrap()` in non-test code.
- **Types cross the API boundary** via `utoipa` (OpenAPI → `openapi.json`), and
  the console consumes them through `openapi-typescript` (`npm run gen:api`) —
  don't hand-write request/response shapes on the TS side.

## Quality standards — what "done" means

The local self-verify bar mirrors `.github/workflows/ci.yml` exactly; run it
before you call a change complete:

1. `cargo fmt --all --check` — no formatting drift.
2. `cargo clippy --workspace --all-targets -- -D warnings` — zero warnings.
3. `cargo test --workspace` — with Postgres up (else pg tests self-skip and you
   have NOT actually verified the data plane).
4. **Eval regression gates** — `eval … --baseline results/baseline.json`. Hard
   gates (RLS leaks / superseded-in-top-3 = **0**) are unconditional; regression
   gates compare the run against the committed baseline (per `EVAL.md` §3.2).
   A baseline change is a deliberate, committed diff via `--write-baseline`,
   never an accident.
5. Console: `npx tsc --noEmit` && `npx vitest run` && `npm run build` (the
   honesty-guard test `kb-data.test.ts` must stay green).

## Design standards

- **RLS is load-bearing, not decoration.** Every runtime query runs through a
  transaction stamped with the caller's `app.org_id` / `app.user_id` (`SET
  LOCAL`), under the non-owner `brainiac_app` role — there is **no unscoped
  query path**. `migrate()` runs DDL as the admin user; the runtime pool drops
  to the constrained role in `after_connect`. Preserve this split; never widen a
  read to bypass `scoped_tx` (see `crates/brainiac-store/src/lib.rs` header).
- **Keep domain math in `core`, Postgres mapping in `store`.** Scoring, fusion,
  reranking, temporal validity, and health are pure and unit-tested in `core`;
  `store` only maps rows ↔ those types and enforces RLS. Don't leak SQL into
  `core` or business math into `store`.
- **Migrations are append-only and numbered** (`migrations/NNNN_*.sql`, applied
  by `sqlx::migrate!`). Add the next number; never edit a shipped migration.
  Read `migrations/README.md` before writing one.
- **The knowledge base is a projection, not a second source of truth** — agents
  write memories, pages follow; there is no bidirectional sync (`README.md` §KB).
- **Console**: Next.js 15 App Router + React 19 + Tailwind 4, `NEXT_DIST_DIR=
  .next-build` for build/start; server-only data access stays behind
  `server-only`; types come from the generated OpenAPI schema.
