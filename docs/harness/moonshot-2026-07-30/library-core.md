## 1. Conformance receipts: turn "an agent fetched the rule" into "the org can prove the rule was followed — and prove the rule was right"

- **Severity**: Critical
- **Category**: agent-feedback-loop
- **File**: `crates/brainiac-store/src/library/usage.rs:13` (`record_usage`) · `crates/brainiac-core/src/library.rs:257` (`LibraryUsageEvent::{Fetch,Check,Apply}`) · `crates/brainiac-server/src/library.rs:460` (`usage_record`) · `crates/brainiac-store/src/library/standards.rs:224` (`adopt_standard`) · `crates/brainiac-store/src/projects.rs:20` (`RepoRow`)
- **Scenario**: An agent starts a session, pulls `standards_for(stack)`, and at the end of the change it does not report "I checked rule X" — it returns a **conformance receipt**: per adopted rule in scope, a verdict (`held | violated | waived | not_applicable`), the file/hunk anchors it judged, and the diff identity it judged them against. The receipt is stored, immutable, RLS-scoped, and addressable. Three things become possible that are impossible today. (a) A maintainer opens a rule and sees not a fetch bar but *"held in 214 of 231 changes touching this surface in 30 days; 12 waivers, 5 violations, here are the diffs"* — compliance as evidence rather than as an agent's self-report. (b) A leader can answer "do our agents actually follow our standards" with a number that has receipts behind it, per team, per stack, without any per-person attribution. (c) The most valuable inversion: **the rule gets graded too.** A rule whose receipts are 60% waivers is not being disobeyed — it is *wrong*, or too broad, or stale. `rule_fitness` (waive rate, violation rate, applicability rate, days since a receipt mentioned it at all) becomes the gate's second instrument, so the normative layer stops trusting only its birth certificate (provenance) and starts being judged by its record in production. Rules that cannot earn a held-rate get raised as deprecation candidates through the machinery that already exists.
- **Root cause**: The usage table is a *touch counter*, not an evidence store. `LibraryUsageEvent::Check` is documented as "an agent compared its work against a standard" and it records exactly that fact — no verdict, no subject, no anchor. `record_usage` has room only for `(kind, artifact_id, version, event, team_id)`. So every downstream number the Library computes (`health_signals`' `standards_dormant`, the console pulse bars, `usage_named`) measures **attention, not obedience**: a rule fetched a thousand times and violated a thousand times looks identical to a rule that is universally honoured. This is the one place where the product's own mission ("an eval harness that proves every claim") is not met by the Library — the normative layer's central claim, *practice follows our norms*, is the one claim nothing can prove. It also means the plan's stated anti-rot mechanism (L5: "the only test of a rule is whether practice follows it") is not actually implemented — only a proxy for it is. And with no verdict corpus, there is nothing to benchmark, so the whole downstream ladder (Never #3's enforcement consent design, per-rule adoption from repo scan, the skill eval harness) has no substrate to stand on.
- **Impact**: 10x on the Library's credibility surface, and it converts the whole layer from opinion-storage into an instrument. Concretely: today an org can report *0* trustworthy compliance facts; after this it can report a held-rate per rule, per stack, per team, per week, each one drillable to the diff. It closes the loop that makes norms self-correcting — the gate currently only ever gains rules (adopt is a one-way door, deprecation is entirely manual and unprompted), so a mature org's rulebook monotonically accretes toward the wiki failure mode the plan set out to avoid. Rule fitness is the first mechanism that can shrink it with evidence. It is also the prerequisite that unlocks Never #3 honestly: an org can only agree a false-positive budget for enforcement once it has measured its own false-positive rate, and receipts *are* that measurement — which means this is the cheapest path to the product's most-requested-but-most-dangerous feature, arrived at with data instead of nerve.
- **Fix sketch**: Additive; the existing usage table stays as the fetch counter and does not move.
  1. **Smallest proving slice** — one new table `library_conformance` (`org_id`, `standard_id`, `standard_rev`, `verdict`, `subject_kind` = `diff|file|session`, `subject_ref` (commit sha / session id), `anchor` jsonb (path + line span), `note`, `team_id`, `occurred_at`), org-scoped RLS + `brainiac_app` grants like every table in 0028, and **no user column**, so Never #1 is a schema property exactly as `library_usage_events` made it. New store module `library/conformance.rs` beside `usage.rs`: `record_receipt(conn, &Receipt)` (batch insert, one tx, warn-only at the call site like `record_usage` — vital signs must never cost an agent its answer) plus `fitness(conn, standard_id, window)` returning `held/violated/waived/n_a` counts. Add `Verdict` to `brainiac-core::library` with the same `as_str`/`parse` round-trip pinned to the migration's CHECK list (`library_vocabulary_round_trips_and_matches_migration_checks` is the test to extend).
  2. **Surface** — `POST /v1/library/conformance` (scope `lib:read`, same as usage; batched: one receipt per rule in one call) accepting slugs *or* ids exactly as `UsageRequest` does, and an MCP tool `standards_report_conformance` funnelled through the same store call so REST and MCP cannot drift (the discipline `standard_propose` already set). `standards_for` grows a returned `rev` per rule so a receipt names the revision it judged — otherwise a re-worded rule silently invalidates its own history.
  3. **Make it visible** — extend the console standards rule detail (`console/app/console/modules/standards/`) so the pulse strip carries a held/waived/violated bar next to the fetch bar, waivers listed with their notes (a waiver with a reason is the single richest triage input the gate has ever had). Add `standards_low_fitness` to `LibraryHealth` in `usage.rs:39` and one attention item, reusing `rule_is_dormant`'s age-guard discipline: a rule with 3 receipts is not unfit, it is new — the signal must not cry wolf.
  4. **Close the loop** — `library_sweep` gains a fourth deterministic miner that raises a *deprecation candidate* for an adopted rule whose fitness is under threshold over a full window, carrying the receipts as its evidence. Same gate, same named human, no new governance story.
  5. **Gate** — `library_pg`: a receipt cannot name a person (schema-shape test, mirroring the existing no-leaderboard test); a receipt against a `proposed` rule is refused (an agent must not attest against something the org has not decided); cross-org receipts are invisible; fitness math with the age guard; a receipt pins `standard_rev` and survives a re-word.

## 2. Norm packs: make an org's ratified judgment a portable, signed, forkable artifact — and let norms compete on measured evidence across orgs

- **Severity**: High
- **Category**: platform-surface
- **File**: `crates/brainiac-core/src/library.rs:216` (`SkillVersion`) · `crates/brainiac-store/src/library/standards.rs:37` (`insert_standard` / `standard_versions`) · `crates/brainiac-store/src/library/bridge.rs:65` (`propose_from_divergence`, the only existing import path) · `crates/brainiac-publish/src/okf.rs:1` (the `Publisher` + `x_brainiac_*` extension precedent) · `crates/brainiac-store/src/library/proposals.rs:88` (the dedup funnel every import must reuse)
- **Scenario**: A **norm pack** is a signed, content-addressed bundle of standards (statement, rationale, verbatim examples, enforcement, category identity, and — the part nobody else can ship — the fitness record from finding 1). A framework author publishes `axum-service-norms@2.1.0`. A regulated-industry consortium publishes a baseline. A consultancy hands its client its own rulebook as an artifact instead of a PDF. An org **subscribes**: every rule in the pack arrives in its triage queue as a `proposed` candidate with `provenance kind = upstream` — never as an adopted rule, so the gate is untouched and Never #2's asymmetry holds for a foreign author exactly as it holds for an agent. The org adopts twelve, rejects three (and the rejection is remembered, so `2.2.0` does not re-litigate them), and locally edits two — and now **the delta between the org's norms and upstream is a first-class object**: "you diverge from the upstream baseline in 5 places, here is each one and the named human who signed it." When `2.2.0` lands, only genuinely changed rules re-enter triage; the org's local edits survive as a three-way merge, not a clobber. And because packs carry fitness, the exchange becomes the first place in the industry where a coding standard can be *ranked by whether it worked*: aggregated, k-anonymised held/waiver rates across subscribing orgs turn "best practice" from an assertion into a measurement — an evidence index that gets better with every org that joins.
- **Root cause**: Every rule in this design is **born local and dies local.** `standards` is keyed `(org_id, slug)`; identity is a per-org slug with a collision suffix derived from a divergence uuid (`bridge.rs:113`) — there is no content address, no author-namespaced identity, and no lineage column, so the same rule in two orgs is two unrelated rows with no way to know they are the same rule. Skills got the open-format treatment (L4: adopt the agent-skill bundle format, do not invent one) precisely so they would be portable, but **standards got no format at all** — the only export that exists is a projected KB page (follow-up 1), which is human prose for readers, not a machine-ingestable artifact, and there is exactly *one* import path in the entire layer: `propose_from_divergence`, from the org's own detector. The plan defers cross-org exchange to follow-up 5 on the grounds of blast radius, which is the right caution about *outbound* leakage and the wrong reason to have no *inbound* path: importing someone else's rulebook has no leak surface at all, and it is the half that creates the network. So today Brainiac's ceiling is "each org builds its rulebook alone from zero" — which caps time-to-value at the speed of one org's own incident history, and caps the product at a tool rather than a network.
- **Impact**: This is the network-effect surface the whole normative layer has been quietly earning the right to build. Time-to-first-adopted-rule drops from *months of accumulated incidents* to *one subscribe call* — a brand-new org's Library goes from empty (and therefore worthless to its agents, and therefore never fetched) to a curated triage queue on day one, which is the difference between a feature orgs eventually use and one they onboard onto. Reach multiplies past the org boundary: one authored pack serves N orgs, and the value flows back — every subscriber's receipts sharpen the pack's fitness numbers, so the pack's author gets an evidence loop no linter vendor has, and each new subscriber makes the index better for the rest (the classic compounding shape, on an asset nobody currently owns). Strategically it also creates a defensible category no competitor is in: not "a linter with rules" but *the registry where norms carry their evidence and their lineage*. And it costs the governance story nothing — an imported rule is a candidate, and only the gate can adopt it.
- **Fix sketch**: Import first, export second, federation last — the risk gradient runs the same direction.
  1. **Give a rule a portable identity** (inbound-only, zero blast radius). Migration adds `standards.content_hash` (sha256 over the normalised statement + category identity, computed in one place in `brainiac-core::library` and tested as stable) plus `derived_from` (`{pack, semver, rule_key, hash}` jsonb) and `upstream` as a third `StandardProvenanceKind` — the one enum addition L-never #4 can absorb, since an imported rule *is* attributed, to a named external author.
  2. **Smallest proving slice**: a norm pack is a directory/tarball in the shape the OKF target already established (`crates/brainiac-publish/src/okf.rs`) — YAML front-matter per rule + markdown body + a `pack.toml` manifest with author, semver, and a detached signature; reuse `SkillVersion`'s content-addressed-blob-in-Postgres precedent (LIBRARY-PLAN deviation 3) rather than inventing storage. New `brainiac-store::library::packs` with `import_pack(conn, &Pack)` that **routes every rule through `proposals::propose_standard`'s existing funnel** — rate limits aside, its slug-or-verbatim-statement dedup plus the rejection memory is precisely the three-way-merge primitive needed, so an upstream rule the org already rejected collapses and is *told*, not re-queued. `POST /v1/library/packs/import` under a new `lib:import` scope (maintainer-only, sibling of `lib:publish`). Console: a "sources" rail on the standards board showing subscribed packs, the local-divergence count, and each divergence's signing human.
  3. **Then outbound**, and only behind the org capability flag follow-up 5 correctly demands: `export_pack` over adopted rules for a stack, through the existing `Publisher` seam so a pack can be published to a git target with no new delivery mechanism, plus the leak-eval matrix (a `proposed`, `rejected`, or internally-scoped rule must never appear in an exported pack — the same class of gate `standards_page_pg` already proves for the projected page).
  4. **Then federation**: an opt-in, aggregate-only fitness contribution keyed by `content_hash` (never rule text, never repo, never team — the same refusal shape the consent-default-OFF work in this product's sibling projects settled on), and a `GET /v1/library/packs/{pack}/fitness` that shows a subscriber how a rule performs in orgs that are not theirs. This step is worthless before finding 1 exists and near-free after it, which is why the two findings are ordered as they are.
  5. **Gate**: `library_pg` — an imported rule is `proposed` with `upstream` provenance and never `adopted`; re-importing the same semver is a no-op; a bumped semver re-queues only rules whose `content_hash` changed; a locally edited rule is not clobbered by an upstream bump and its divergence is reported; an upstream rule matching a local rejection collapses and returns the rejection; an unsigned or hash-mismatched pack imports nothing.
