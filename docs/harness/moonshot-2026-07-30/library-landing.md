## 1. The public shelf — make `/library` the first live shelf in an internet of citable org standards

- **Severity**: Critical
- **Category**: platform-surface
- **File**: `console/app/library/page.tsx:5` (the "makes no API call and holds no token" comment) · `console/src/library/sections/Drift.tsx:42` (`<DriftBeat />`, a synthetic pulse) · `crates/brainiac-server/src/library.rs:46` (`routes()`, every path behind `auth_of`) · `crates/brainiac-server/src/http.rs:110` (`.merge(crate::library::routes())`) · `migrations/0028_library_substrate.sql` (`standards`, `standard_provenance`, `library_usage_events`) · `docs/VISIBILITY-TIERS.md` (ladder is `private | team | org`, no public rung, by explicit refusal)

- **Scenario**: A staff engineer at another company reads a tweet and lands on `brainiac.dev/l/brainiac`. It is not a marketing page about standards — it *is* Brainiac's own adopted standards, live: 41 rules by stack, each with its statement, its good/bad example, its enforcement strength, its real pulse ("fetched 1,180 times in 30 days by 6 teams"), and its provenance rendered as counts ("backed by 3 incidents and 1 resolved dispute"). She hits `import` on four of them. In her org they land as `lifecycle='proposed'` with `standard_provenance.kind='upstream'` pointing back at the shelf they came from, and her maintainer ratifies two. A week later her own coding agent, in a repo Brainiac has never seen, runs `standards_for` against a *public* shelf with no token at all — the way an agent today fetches from npm. And back on Brainiac's shelf a number nobody has ever been able to compute appears next to each rule: **how many other organizations kept it.** Six months on, `/l/vercel/next-app-router`, `/l/stripe/money-handling`, `/l/{yourcompany}` are addressable, forkable, versioned URLs, and "which public shelf does your org inherit from" is a question with an answer.

- **Root cause**: The Library's entire ceiling is set by one line in `http.rs`: *"Every handler resolves the bearer token to a principal FIRST; there is no anonymous data path."* Every rule Brainiac governs is invisible outside the org that wrote it, so a standard can only ever be as valuable as one company's internal adoption. That makes the Library a *feature* — a better internal style guide — when the same substrate is one visibility rung away from being a *protocol*. The landing page is the tell: the product's most differentiated claim ("a standard is a governed artifact with vital signs") is argued by a surface with no artifacts and no vitals, because there is nowhere for a real rule to be shown to a stranger. `VISIBILITY-TIERS.md` refuses a public rung on leak grounds — correctly for *memories*, which are raw org context. But an **adopted standard is the one memory-derived artifact an org wants quoted**: it is already maintainer-ratified, already prose written for outsiders to follow, already the thing companies publish as engineering blogs today. Public-by-opt-in is not a leak in the standards lane; it is the point of the lane.

- **Impact**: Turns a single-tenant governance tool into a two-sided network. (a) **Reach**: from N paying orgs each seeing their own rules, to every coding agent on the internet able to fetch a shelf anonymously — the same distribution shape that made npm and Docker Hub categories rather than products. (b) **A new signal class that no competitor can fake**: cross-org adoption of a rule. Today the strongest evidence for a standard is one org's own usage telemetry; with shelves, a rule carries "kept by 340 orgs, dropped by 12" — an authority score mined from practice at internet scale, which is exactly the product's thesis applied one level up. (c) **Zero-cost acquisition**: every shelf is a public page an org has an incentive to make good, hosted by you, linking to you, and the `import` button is a signup funnel that starts with the user's *own* standards already half-built. (d) It retires the page's credibility problem permanently: nothing argues "give your rules a pulse" like a page whose numbers move.

- **Fix sketch**:
  1. **Make publicness a schema property, not handler etiquette** — matching this repo's existing habit of putting promises in the database (`standards_attribution_check` constraint trigger, and `library_usage_events` having no user column at all). New migration after `0037_divergence_axis.sql`: `shelves (org_id, handle UNIQUE, title, blurb, enabled)` plus `standards.shelf_visible boolean NOT NULL DEFAULT false`. Add a Postgres role `brainiac_public` whose policy on `standards` / `standard_versions` is `shelf_visible AND lifecycle = 'adopted'` instead of `org_id = current_setting('app.org_id')`. Publicness then cannot be leaked by a handler bug — an un-flagged rule is invisible to that role.
  2. **One anonymous read module**: `crates/brainiac-server/src/shelf.rs` with `GET /v1/shelf/{handle}` and `GET /v1/shelf/{handle}/{slug}`, merged in `http.rs` beside `/health` and `/openapi.json` (i.e. *before* the token-resolving merges), on a second `PgPool` connected as `brainiac_public`. Reuse `StandardView` but redact through a new `PublicStandardView`: drop `standard_provenance.ref_id` (return `{kind, count}` pairs — the provenance *argument* survives without the evidence leaking), and collapse `TeamUsageView` into one aggregate `{uses, teams: i64}` so team names never cross the boundary. Flipping `shelf_visible` is `lib:publish` only, alongside `standard_adopt` in `library.rs`.
  3. **Smallest slice that proves it** — do only this first: env `BRAINIAC_SHELF_HANDLE`; convert `console/app/library/page.tsx` to a server component with `export const revalidate = 300` (ISR, so the marketing page never takes a request-time API dependency) fetching the shelf through a new *non-`server-only`* public client beside `console/src/lib/api.ts`; replace `<DriftBeat />` in `Drift.tsx:42` with three real adopted rules and their real pulse, and keep the existing fixtures as the `withDemoFallback` path (`console/src/lib/demo-fallback.ts`) so the page survives an API outage. One page, one endpoint, no new concepts — and the hero stops being a drawing of a claim.
  4. **Then the flywheel**: extend `standard_provenance`'s `kind` check with `'upstream'` (`ref_id` = `handle/slug`); add `POST /v1/library/standards/import` (`lib:publish`) that copies a public rule in as `lifecycle='proposed'`, `origin='upstream'` — note it enters *triage*, never adoption, so the Never-list asymmetry holds across orgs exactly as it does inside one. Aggregate upstream counts back onto the shelf view. Add an optional `shelf` argument to the `standards_for` MCP tool (`crates/brainiac-server/src/mcp.rs:217`, currently `lib:read`) so a tokenless agent can read a public shelf — that call is the protocol.
  5. Handles and `/l/{handle}` routing last; the mechanism is proven by step 3 and the network exists at step 4.

## 2. Attestation — every public claim bound to a running prover, starting with this page's own

- **Severity**: High
- **Category**: verifiable-claims
- **File**: `console/src/library/library-data.test.ts:36` (`PLAN_TRUTH`, a hand-maintained constant) · `console/src/library/library-data.test.ts:46` (`ALL_PAGE_TEXT` — covers only `library-data.ts`) · `console/src/library/sections/StatusLadder.tsx:15` · `console/src/library/sections/Finale.tsx:36` · `console/src/library/sections/Anatomy.tsx:26-29` · `console/src/library/primitives.tsx:41` (`Stamp`) · `crates/brainiac-server/src/sweeps.rs:269` (the `execute` match over sweep kinds)

- **Scenario**: Every claim on a Brainiac-published surface carries a live verdict. The status ladder does not render a hand-typed stamp; it renders `● verified · checked 6m ago`, and hovering says which prover ran — *"no adopted standard exists without provenance or a named decree"* proved by a SQL predicate against the real database, *"a rule unused for a month raises an attention item"* proved by a `brainiac-eval` profile, *"usage cannot store a person"* proved by a schema introspection that fails if a `user`-shaped column ever appears on `library_usage_events`. A claim whose prover has not run in 24h renders **stale**, publicly, without anyone deciding to be honest that morning. Then the same machinery turns outward: a customer's published wiki page pins its assertions to provers in their repo — "our p99 checkout latency is under 300ms", "no service writes to the ledger directly" — and the page goes visibly stale or red on its own. The doc-wiki stops being the place knowledge goes to rot, because rot now has a verdict.

- **Root cause**: This context invented the mechanism and then capped it at a test file. `library-data.test.ts` pins page stamps to a *transcription* of the plan's status log (`PLAN_TRUTH`), and `ALL_PAGE_TEXT` flattens only `library-data.ts` — so claims written as JSX prose are entirely unguarded. That gap is not hypothetical, it is currently live and shipping: `LADDER` and `PROPERTIES` are 100% `shipped`, while `StatusLadder.tsx:15` still tells visitors *"almost all of it roadmap, on purpose"*, `Finale.tsx:36` still says *"What remains is the console, the mining, and the agents' own proposals"*, and `Anatomy.tsx:26-29` still says *"The vital signs stay stamped roadmap for one honest reason"*. **The page whose entire argument is that unmeasured claims drift is, right now, the surface in this product most demonstrably drifted from its own truth** — proving its own thesis at its own expense. The constraint being lifted is that honesty is implemented as a *snapshot compared to a snapshot*, when the product already owns the machinery for continuous re-verification (`raw_ttl` sweep, memory reverify in `brainiac-store/src/memories.rs`, `brainiac-eval`'s `drift_profile.rs`) and has never pointed it at assertions.
- **Impact**: (a) Closes the credibility loop the product's mission statement already promises — *"an eval harness that proves every claim"* — by making the harness's output a *public, addressable, continuously refreshed* artifact rather than a CI log nobody outside sees. (b) Creates a category no knowledge tool occupies: **documentation that cannot overstate.** Every competitor's wiki decays silently; a Brainiac page with 12 pinned claims and 12 running provers decays loudly. That is the single most defensible thing a knowledge product can sell, and it generalizes to every `documents` row, not just this page. (c) Force multiplier on the shelf in finding #1: a public standard whose claims are attested is worth citing; an unattested one is someone's opinion in a nice font. (d) Immediately fixes three live false statements to visitors, and makes that class of regression structurally impossible instead of vigilance-dependent.

- **Fix sketch**:
  1. **Smallest slice, ship today, zero backend**: widen `ALL_PAGE_TEXT` in `library-data.test.ts:46` to also read the string literals of `sections/*.tsx` (glob + source scan, the audience-rule regexes already work on flattened text) and assert no rendered prose says `roadmap`/`what remains`/`not built` while every `LADDER`, `PROPERTIES` and `RULE_STAGES` status is `shipped`. That one test turns red on the three drifted lines above and is the proof-of-concept for the whole idea: a claim is checkable by a prover.
  2. **Model claims as records**: new migration — `claims (id, org_id NULL for product-level, surface, statement, prover_kind ('sql'|'eval_profile'|'test'|'http'), prover_ref, expect, last_run_at, verdict ('pass'|'fail'|'stale'), detail, run_ms)`. Backfill the 6 `LADDER` phases, 5 `PROPERTIES` and 4 `NEVER` entries as the first 15 rows — `PLAN_TRUTH` becomes a query result instead of a constant someone must remember to edit.
  3. **Run them where sweeps already run**: add an `attest` arm to the match in `crates/brainiac-server/src/sweeps.rs:269` (kinds are already `divergence | health_snapshot | raw_ttl | alerts | library`), with a row in `sweep_schedules` so it inherits the existing operator surface (`GET /v1/ops/sweeps`, `POST /v1/ops/sweeps/{kind}/run`) and result recording (`record_result`) for free. `sql` provers run a predicate on the admin pool; `eval_profile` provers invoke a `brainiac-eval` profile the way `drift_profile.rs` does and assert a threshold. Start with the three cheapest and most load-bearing: the attribution constraint, the no-person-column schema check, and the dormant-rule health signal (`brainiac-store/src/library/usage.rs::health_signals`).
  4. **Publish the verdicts**: `GET /v1/attest/{surface}` on the same anonymous public pool built in finding #1 (these two moonshots share exactly one piece of infrastructure — build it once). Add a fourth state to `Stamp` in `primitives.tsx:41` — `verified`, carrying the age of the last run — and let `StatusLadder` and `Anatomy` render verdicts instead of literals.
  5. **Then turn it on customers**: pin claims to `documents` rows (kind `standards_page` already exists per `0031_standards_pages.sql`, and `mark_standards_pages_dirty` already models a page needing recomputation) so a published wiki page renders each assertion's verdict, and a stale claim marks the page stale. This is the memory TTL/reverify loop extended from *facts* to *assertions* — same cadence machinery, an entirely new product surface.
