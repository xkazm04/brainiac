## 1. The extractor that learns from its own org — per-org versioned extraction policies, tournament-gated

- **Severity**: Critical
- **Category**: self-improving-extraction
- **File**: `crates/brainiac-pipeline/src/extract.rs:24` (`EXTRACT_SYSTEM_PROMPT_V1`), `extract.rs:487` (`extract_once`), `extract.rs:581` (`run_extract`); anchors: `crates/brainiac-pipeline/src/worker.rs:560` (the only call site), `crates/brainiac-pipeline/src/policy.rs:23` (`PolicyEngine::evaluate`), `migrations/0001_init.sql:168` (`promotions`), `migrations/0004_memory_feedback.sql:5` (`memory_feedback`), `crates/brainiac-eval/src/extraction_profile.rs:44` (`MATCH_THRESHOLD`), `crates/brainiac-pipeline/src/reembed.rs:1` (the backfill-sweep precedent)

- **Scenario**: An org has been running Brainiac for three months. Its maintainers have approved 900 candidate memories and rejected 300 in review; agents have marked 200 retrieved memories `helpful` and 40 `wrong`; the faithfulness judge has flagged paragraphs; contradictions have been resolved with a winner. That is a **labelled extraction corpus of this org's own knowledge**, produced for free by the governance loop. Today none of it reaches the extractor. In the world this finding creates, the extractor for `acme` is not a `const &str` — it is `extraction_policy v7 (acme)`: the same V1 rubric plus twelve few-shot exemplars drawn from *this org's* approved memories over *this org's* transcript style, a short negative list distilled from what reviewers repeatedly rejected ("we reject standup status as `fact`"), and the org's canonical entity vocabulary so the model stops re-coining `psp-gw` next to `psp-gateway`. A candidate policy v8 is built weekly from newer labels, run in **shadow** on a sample of live sources, scored against both the Meridian gold (`extraction_profile`) and the org's own reviewer verdicts, and promoted only if it wins on both. When it wins, the archived `sources.raw_text` corpus — every transcript ever ingested, still sitting in Postgres and never re-read since — is re-mined by the better extractor, so *past* knowledge improves too. Across tenants, the operator sweep aggregates only the *structural* deltas that keep winning (rubric wording, negative categories, kind-boundary clarifications — never any org's content), producing a house prior so customer #50's day-one recall starts where customer #1's month-three recall ended.
- **Root cause**: Extraction quality is a compile-time constant. `extract_once` hardcodes `EXTRACT_SYSTEM_PROMPT_V1`, temperature 0.0, no exemplars, no org context; `run_extract` takes an org id but nothing org-*specific*. The doc comment at `extract.rs:14-23` is the proof that this ceiling is real and already binding: a hand-written V2 rewrite was attempted and the `extraction` eval **rejected** it (recall 0.458 → 0.29 / 0.17). The conclusion drawn was "V1 stands". The correct conclusion is stronger: **human prompt authorship is exhausted as a lever**, so the only remaining lever is a measured search over prompts driven by real labels — and the repo already owns both halves (a labelled corpus in `promotions`/`memory_feedback`, and a semantic scorer in `extraction_profile` with a baseline-gate discipline in `gates.rs`) and has wired them to nothing. Meanwhile `PolicyContext` (`policy.rs:12`) carries exactly one signal, so review load never falls either: `default_needs_review` fires for almost everything, and the human queue grows linearly with ingest volume forever.
- **Impact**: The stated recall today is **0.458** on the extraction profile — the pipeline drops more than half the durable knowledge in a transcript, which is the single largest loss of value in the entire product (nothing downstream — retrieval, KB pages, MCP — can serve a memory that was never extracted). Every 0.1 of recall is ~22% more knowledge captured from the *same* already-paid-for transcripts and the same token spend. A learning loop that closes even half the gap to 0.8 roughly **doubles the knowledge yield per source at zero extra ingest cost**, and does it retroactively over the archived corpus. Second-order: exemplar-conditioned extraction plus reviewer-derived negatives is what lets `PolicyEngine` earn broader auto-approval rules with evidence (measured reviewer-agreement per rule), which converts governance from an O(volume) human tax into a sampled audit — the difference between an org that can ingest 50 transcripts a week and one that can ingest 5,000. And the cross-org structural prior is a compounding moat no single-tenant competitor can copy: each tenant makes the product measurably better for the next.
- **Fix sketch**:
  1. **Seam first, byte-identical.** Introduce `extract::ExtractionPolicy { version: i32, system_prompt: String, exemplars: Vec<Exemplar>, negatives: Vec<String>, vocabulary: Vec<String> }` and a `Default` that renders exactly `EXTRACT_SYSTEM_PROMPT_V1` with empty vectors. Thread `&ExtractionPolicy` through `run_extract` → `extract_once` (replacing the two `EXTRACT_SYSTEM_PROMPT_V1` literals at `extract.rs:490` and `extract.rs:526`) and record `policy_version` on the `pipeline_runs` row next to `model_ref` in `write_pipeline_run` (`worker.rs:490`). Ship this alone: zero behaviour change, and the eval proves it (`extraction` profile must reproduce 0.458).
  2. **Harvest labels.** A deterministic miner in the shape of `library_sweep` (no LLM, org's own words verbatim): positives = memories whose `promotions` row has `reviewer_id IS NOT NULL` and a successful transition, weighted up by `memory_feedback.verdict = 'helpful'`; negatives = memories rejected in review or fed back as `wrong`, clustered by `kind` to yield category-level negative statements. Join through `provenance.source_id` (the same join `memory_exists_for_source` already uses at `extract.rs:567`) so each exemplar keeps the transcript excerpt it came from.
  3. **Store and resolve.** `extraction_policies (org_id, version, body jsonb, status: shadow|active|retired, eval_scores jsonb, created_at)`, RLS-scoped like every governance table; the worker resolves the org's `active` row once per tick and falls back to `Default` when there is none.
  4. **Tournament.** A `shadow` policy runs on a sampled fraction of live sources in a *second* extraction pass whose memories are written nowhere — scored in-process with the `extraction_profile` matcher (embedding cosine at `MATCH_THRESHOLD`) against (a) the Meridian gold and (b) the org's own approved memories for that source. Promotion requires beating the active policy on both, using the `gates.rs` baseline discipline (embedder + provider must match, or refuse the comparison). This is the mechanism that would have caught the V2 regression *before* anyone hand-wrote it.
  5. **Re-mine.** A `reextract` sweep modelled directly on `reembed.rs`: cross-org admin pool, resumable, idempotent (the "no memory for this (source, policy_version)" query *is* the resume point), re-running the winning policy over archived `sources.raw_text`. The existing `(source, content)` dedup at `extract.rs:677` already makes re-extraction safe — only genuinely *new* memories land, each as a fresh `raw` candidate through the normal gate.
  6. **Cross-org prior (last).** The operator sweep compares winning policy bodies across tenants and proposes structural deltas — rubric phrasing and negative *categories* only, with a hard refusal on any exemplar text or entity name — into the same triage-and-a-named-human-adopts pattern `library_sweep` already established.

## 2. The repo as the ground truth the pipeline reads and re-proves against

- **Severity**: Critical
- **Category**: ground-truth-ingestion
- **File**: `crates/brainiac-pipeline/src/worker.rs:551` (`get_source_text` — the entire input surface), `crates/brainiac-pipeline/src/extract.rs:589` (the `source_kind` switch), `migrations/0001_init.sql:40` (`sources.kind` comment already lists `repo`, nothing ever writes it), `migrations/0034_projects_onboarding.sql:34` (`project_repos` — remotes registered, contents never read), `crates/brainiac-pipeline/src/divergence.rs:1` (memory-vs-memory adjudication, the pattern to invert), `crates/brainiac-pipeline/src/okf_ingest.rs:1` (the closest precedent: files → sources → the normal gate)

- **Scenario**: `project_repos` already knows every repo each project owns, and onboarding already proves who may speak for it. Today Brainiac's beliefs about that code come exclusively from humans *talking about* it — and every belief then rots on a **calendar** (`ttl_days` at `extract.rs:321` stamps `valid_to` from a per-kind constant, so a memory is presumed true for 180 days whether or not the code it describes was deleted last Tuesday). In the world this creates, the pipeline reads the code. Two directions, one mechanism. **Inbound**: merged diffs, ADR/README/migration/config files, and PR descriptions become `repo`-kind sources flowing through the *same* chain a transcript takes — extraction, contradiction, promotion gate, review — so the org's decisions get captured from the artifact that proves them, not just from whoever happened to narrate them in a call. A migration that adds a unique index, a config default that changed, a dependency that was dropped: each is a durable `fact`/`decision` nobody will ever write a memory for by hand. **Outbound and more valuable**: every candidate memory that names an entity mapped to a repo gets a **grounding check** — the pipeline retrieves the code the memory claims to describe and asks whether HEAD still supports the claim. A memory whose evidence still holds is *re-verified with a citation*; one whose evidence vanished opens a contradiction against reality itself and its `valid_to` collapses to now. The reviewer stops reading assertions and starts reading assertions **next to the code that proves or refutes them**, and `PolicyEngine` finally gets a signal worth auto-approving on: `grounded_in_code`.
- **Root cause**: The pipeline's entire world is one column. `worker.rs:551` reads `(team_id, source_kind, raw_text, project_id)` and everything downstream is a function of `raw_text` — so ingest volume is capped by human narration bandwidth, and truth-maintenance is capped by having no external referent to check against. Nothing in the workspace reads repo content (verified: no `git2`, no GitHub content fetch, no clone path anywhere in `crates/`); `project_repos` is an attribution table only. `divergence.rs` shows the sophistication the repo can already reach in adjudicating knowledge — but only memory *against memory*, i.e. the org's beliefs checked against the org's other beliefs, which cannot detect a claim on which everyone is confidently, uniformly stale. (Note: the queued "repo access proof (GitHub token)" item is the *credential* enabler for this, not this — it grants no ability to ingest or verify anything.)
- **Impact**: A mature org's repos contain **one to two orders of magnitude more durable, extractable knowledge than its transcripts**, and unlike transcripts they arrive continuously, self-describing, and free — this is the difference between an ingest ceiling set by how much people talk and one set by how much they ship. On the trust axis the claim is sharper: today the honest confidence in a 90-day-old memory is unknown, so `mission: "retrieval quality an agent can trust"` currently rests on human review plus a timer. Evidence-anchored re-verification replaces "probably still true" with "verified against `HEAD@abc123` on 2026-07-28, citation attached" — the single highest-value property an agent-facing memory can carry, and the thing that makes an agent's *automatic* use of a memory defensible rather than optimistic. It also converts TTL from a cost centre (a re-verification queue humans must drain) into an automated sweep, which is what lets one maintainer govern 10,000 memories instead of 500.
- **Fix sketch**:
  1. **A pull-side source adapter, narrow first.** `pipeline::repo_ingest`, shaped exactly like `okf_ingest` (which already proves the pattern: read files → `insert_source_idempotent` keyed by path + content hash → `enqueue_source`, with `MAX_FILES`/`MAX_FILE_BYTES` bounds and a refusal to harvest Brainiac's own output). Slice one reads a **local checkout path** for a registered `project_repos.remote` and ingests only high-signal files (`ADR*`, `docs/**.md`, `migrations/**`, `*.toml`/`*.json` config) as `kind = 'repo'` sources with `project_id` already resolved. No network, no credential, no new auth surface — and it lands real memories on day one.
  2. **A `repo` extraction path.** Add a third arm to the `source_kind` switch at `extract.rs:589` alongside `manual`'s verbatim path: a code-aware prompt whose rubric is "state only what this artifact establishes", with `detail_md` carrying the verbatim snippet (`clean_detail` at `extract.rs:185` already redacts and bounds it — the secret firewall matters far more on code than on prose) and the file path + commit going onto the `provenance` row via the existing `insert_provenance` call at `extract.rs:644`.
  3. **Diff-driven, incremental.** Extend the adapter to ingest a *changed-file set* between two commits, storing the commit sha as `sources.external_ref`. Cursor state per repo means each merge costs one small extraction, not a full re-scan — the same "only what changed" economy `okf_ingest` gets from its content hash.
  4. **The grounding check — the real prize.** A `pipeline::grounding` stage in the shape of `divergence.rs`: for each candidate memory, take its linked entities (`memory_entities`), map them to repos and to the file paths already cited by `repo`-kind provenance rows, fetch those artifacts, and ask the provider a strictly-bounded question — supported / refuted / no evidence — with the file+line it relied on. Store the verdict as a `grounding` record carrying `(commit_sha, paths, verdict, checked_at)`. Conservative like `divergence`: only `refuted` and `supported` are stored, `no evidence` is silence.
  5. **Wire it to the two places it pays.** `PolicyContext` (`policy.rs:12`) gains `code_grounding: Option<Grounding>`; `supported` becomes a rule that can auto-approve where today `default_needs_review` fires, and `refuted` joins `contradiction_pending` as a hard hold. Separately, a `refuted` verdict clamps `valid_to` to now, so re-verification is finally driven by evidence instead of `ttl_days`' calendar constant — and a `supported` verdict extends it *with a citation*, which is what a reviewer, an auditor, and an agent all actually want to see.
