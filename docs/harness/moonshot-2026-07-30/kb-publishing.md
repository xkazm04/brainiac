## 1. Memory-grade signed bundles: turn OKF export into a knowledge peering protocol

- **Severity**: Critical
- **Category**: network-effect
- **File**: `crates/brainiac-publish/src/okf.rs:110` (`frontmatter`) · `crates/brainiac-pipeline/src/okf_ingest.rs:274` (the `brainiac_origin` refusal) · `crates/brainiac-publish/src/lib.rs:57` (`PageMeta`) · `crates/brainiac-publish/src/render.rs:21` (`memory_url`) · `crates/brainiac-store/src/publishing.rs:12` (`PublishTarget`)
- **Scenario**: Today two Brainiacs cannot exchange a single fact. The OKF target already emits the one thing no other wiki producer emits — `x_brainiac_cited_memories`, `x_brainiac_policy`, `x_brainiac_stale` — and the harvest path already recognizes that frontmatter and **throws the file away** (`stats.own_pages`), because "our own projection is not evidence". Correct for a self-loop; catastrophic as a global rule, because it means *every* Brainiac-authored bundle is unreadable by *every other* Brainiac. Lift that and the export stops being prose-for-humans and becomes an **interchange format for governed belief**: alongside `index.md` / `log.md`, the bundle carries `memories.jsonl` (one record per `org`-visible memory that composed a page: `kind`, `lifecycle`, `content`, `detail_md`, `valid_from/valid_to`, `superseded_by`, `confidence`, entity anchors — the fields already on `brainiac_core::Memory`) plus a `manifest.json` of content hashes signed with a key named by an env var (never in the DB, invariant 4 preserved). Then: a platform team publishes its signed pack and forty product orgs *subscribe* to it; an acquired subsidiary running its own Brainiac peers with the parent instead of being force-merged into one org; a vendor or consultancy ships a versioned knowledge pack whose claims arrive dated, superseded-aware and signed, so an agent asking "how do we do auth with $vendor" gets governed vendor truth instead of 2023 training data. Imported claims land as candidates at a *foreign* trust tier, never as canon, and the existing contradiction engine adjudicates them against local belief — so subscribing is not trusting.
- **Root cause**: The bundle's unit of exchange is a **rendered page**, and provenance is a bare local UUID. `[m:uuid]` resolves only through `render::memory_url(console_url, id)` — the origin console — so outside the publishing org a citation is a dangling pointer, which is exactly why the only honest thing the harvester can do with a foreign Brainiac bundle is to re-extract its prose with an LLM (lossy, expensive, and it launders composed model text back into candidate memories) or refuse it. The refusal keys on *format* (`k.starts_with("x_brainiac_")`), not on *identity*: there is no org fingerprint, no signature, no origin table, so "my own page coming home" and "a peer's governed corpus" are indistinguishable. Consequence: knowledge value per org is linear in that org's own ingestion, and the product has no compounding asset. Every customer independently re-learns the same platform, vendor, OSS and regulatory facts.
- **Impact**: Converts a single-tenant memory server into a network whose value grows with participants. Concretely: (a) importing a 2,000-memory peer pack costs **zero extraction LLM calls** versus ~2,000 today (the whole cost curve of "ingest someone else's wiki" collapses, and quality stops depending on extraction recall — the exact gate that keeps KB3 switched off); (b) day-1 corpus for a new org goes from empty to whatever the network publishes, killing the cold-start that makes the layer "dead weight on single-team work"; (c) `practice_divergences` (already built, cross-*team*) generalizes to cross-*org* on opt-in packs — "71% of peer orgs deprecated this pattern last quarter" is a claim no competitor can make without this substrate; (d) it makes the "GitOps" half of the name literal: knowledge packs are versioned, diffable, reviewable and distributable exactly like dependencies, over git remotes the customer already has.
- **Fix sketch**: (1) **Emit.** New `crates/brainiac-publish/src/federation.rs`: extend the per-page meta gathering in `publish_org` (lib.rs:228-248, which already loads `revision.composed_from`) to collect the full memory rows once per run, and write `memories.jsonl` + `manifest.json` (per-file SHA-256 from the workspace `sha2`, signed with the workspace `rsa` — both already vendored for Vertex JWT, so no new crypto dependency, no C toolchain). Add `org_fingerprint` + `origin_console_url` to the manifest and to page frontmatter as `x_brainiac_org`. Gate the whole sidecar behind an `export_memories: bool` in `OkfConfig` (default **off**, same posture as `kb_enabled`): the first bundle to leave a building must be a deliberate act. Reuses the existing per-page `org`-visibility filter (lib.rs:210) unchanged — the leak rule is the same rule. (2) **Subscribe.** Migration: `publish_targets` gains nothing; add `knowledge_subscriptions` (org_id, source kind `okf-dir`/git remote, peer fingerprint, trusted public key ref, enabled) and `memory_origins` (local memory_id, peer fingerprint, origin memory_id, origin revision, imported_at, signature_ok). Fork `okf_ingest.rs`'s `brainiac_origin` branch three ways: **own fingerprint → refuse** (today's invariant, kept and now precise), **known peer + valid signature → federated import** (structured, no extractor: insert candidates via the promotion path with `memory_origins` attribution and confidence damped by peer trust), **unknown or unsigned → today's behaviour** (refuse loudly). Upstream deprecation of an imported memory propagates through the existing dirty-marking, so pages citing a withdrawn peer claim recompose. (3) **Resolve citations.** `render::memory_url` takes the origin console for imported memories, so provenance survives the trip in both directions. (4) **First slice that proves it, one session:** extend `crates/brainiac-publish/tests/okf_pg.rs` (which already builds two orgs, `ctx.a` / `ctx.b`, and drives real `publish_org` under RLS) with a round trip — A publishes with `export_memories`, B subscribes to A's directory, B ends up with candidate memories carrying A's fingerprint, **zero LLM calls**, a tampered `memories.jsonl` is refused, and a `team`-visible memory of A's never appears in the bundle at all (leak = build failure, the existing posture).

## 2. Reconciliation: publish becomes a two-way sensor, and the org's whole existing wiki becomes auditable

- **Severity**: High
- **Category**: platform-surface
- **File**: `crates/brainiac-publish/src/git.rs:80` and `crates/brainiac-publish/src/okf.rs:168` (blind `fs::write`) · `crates/brainiac-publish/src/confluence.rs:104` (blind version bump) · `crates/brainiac-store/src/publishing.rs:79` (`Publication` — no content hash) · `crates/brainiac-pipeline/src/okf_ingest.rs:197` (`concept_files`) · `crates/brainiac-eval/src/drift_profile.rs:1` (the calibrated detector with no product around it)
- **Scenario**: The pointer block tells agents "NEVER edit files under `docs/okf/`" and the banner tells humans "do not edit here" — and then the publisher enforces it by *silently destroying* whatever they wrote. Nobody is told, nothing is recorded, and the single highest-signal event in the whole system (a human cared enough to correct the org's published account) is discarded on the next tick. Meanwhile the drift detector — claim-vs-corpus classification into `aligned` / `drifted` / `unmatched`, with a zero-tolerance false-alarm gate already green on fixtures (`fixtures/v1/drift/docs.yaml`) — exists only as an eval instrument, DB-free, with its own header admitting the production integration is unbuilt. Wire the two together and the publish surface inverts: before writing, the target **reads what is live**; if the live artifact differs from the hash we pushed, the diff is captured as a witness statement through the same extraction + review gate that `POST /v1/docs/{slug}/edit` already uses ("captured, never saved"), *then* the page is overwritten. The human's correction reaches canonical memory the only legitimate way, and the page they fixed recomposes to say what they meant — with their name on the proposal. Generalize the reader one step and the same loop points at documentation Brainiac never published: a repo's `docs/` tree, a Confluence space. Every claim in 4,000 legacy pages gets classified against governed memory, and the org gets a **documentation trust map** — which pages contradict what the company actually believes, ranked by read traffic, with `unmatched` claims offered as harvest candidates.
- **Root cause**: The `Publisher` trait is write-only (`publish`, `finish`) and the publication ledger stores `revision_id` + `external_ref` but **no hash of the bytes we pushed** — so the system is structurally incapable of noticing that the external artifact diverged, which is why "one-way" had to be implemented as *overwrite and forget* rather than *reconcile*. Second constraint: the only inbound doc path is a manual CLI (`brainiac okf-harvest`, main.rs:387) restricted to OKF-shaped bundles, so Brainiac's knowledge of the company's existing documentation is exactly zero. The product therefore requires the customer to adopt the memory layer *before* it can demonstrate value on the corpus they already have — a cold-start problem for a capability that ships off by default.
- **Impact**: (a) Closes the D4 one-way limitation **without** bidirectional sync — the asymmetry survives intact (nothing writes canon except through the review gate), so this is the one version of "Confluence harvest" that does not put the rot back. (b) Multiplies the ingestion surface from "what agents told us" to "every document the org has ever written": a 4,000-page wiki is ~4,000 free witness statements, versus a corpus built one transcript at a time. (c) Creates a wedge that needs no adoption: a "your wiki is 38% contradicted, here are the 50 worst pages by readership" report is sellable on day one, to a buyer who has not enabled `kb_enabled`, and it lands the customer already holding the evidence for why they need the projection model. (d) Turns the currently-discarded `stats.own_pages` bucket into the highest-conversion review-queue input in the product — edits humans made *on purpose* to pages they read.
- **Fix sketch**: (1) **See the divergence.** Add `async fn fetch(&self, external_ref: &str) -> Result<Option<String>>` to the `Publisher` trait (default `Ok(None)`, so Confluence can adopt it later): git/OKF read the file, Confluence GETs the page body it already fetches for the version number (confluence.rs:91). Migration: `document_publications` gains `pushed_hash text` (SHA-256 of the exact bytes handed to the target), set in `record_publication` — the smallest possible schema delta and the only one this needs. In `publish_org`'s per-target loop (lib.rs:265-317), when `fetch` returns content whose hash ≠ `pushed_hash`, record a divergence and continue to overwrite: never block the push on a stranger's edit. (2) **Capture it.** Route the divergent content into the existing witness framing — `okf_ingest::source_text` already frames a doc as "a document from the repository's knowledge wiki … states", and `insert_source_idempotent` already dedupes by content hash — with a new source kind `page_edit_external` and the page's slug in the frame, so extracted candidates arrive pointed at the page they came from. Add `PublishStats::diverged`, and surface it in the console reviews module as "someone edited this page in Confluence — N proposed updates". (3) **Generalize the reader.** Promote the classifier out of the eval crate into `crates/brainiac-pipeline/src/drift.rs` running against the real corpus (current vs superseded nearest-neighbour, `MATCH_THRESHOLD` 0.70 / `DRIFT_MARGIN` 0.05 as calibrated), reusing `okf_ingest::concept_files` + `MAX_FILES` + `idempotency_key` as the generic doc-tree walker, driven by a new `doc_audit` job kind on the existing SKIP-LOCKED queue. `drifted` → proposed supersessions in the review queue; `unmatched` → harvest candidates; `aligned` → a confirmation counter, because telling authors which pages are *right* is what buys permission for the rest. (4) **First slice:** the reconciliation half only — `pushed_hash` + `fetch` on the git target + a test in `crates/brainiac-publish/tests/okf_pg.rs` that publishes a page, mutates the file on disk as a human would, re-runs `publish_org`, and asserts one source row captured with the human's text and the page restored. That single test is the proof the one-way rule and the round trip can coexist; the audit surface is the follow-on it earns.
